## 1. 经典方案：读写锁 (Read-Write Lock)

使用 C++17 的 `std::shared_mutex`。多个线程可以同时获取读锁，而写锁是独占的。

```cpp
#include <iostream>
#include <shared_mutex>
#include <mutex>
#include <string>
#include <unordered_map>

class UserStatusCache {
private:
    std::unordered_map<int, std::string> cache_;
    mutable std::shared_mutex rw_mtx_; // 读写锁

public:
    // 【读操作】：多线程共享读锁，互不阻塞
    std::string getStatus(int user_id) const {
        std::shared_lock<std::shared_mutex> lock(rw_mtx_);
        auto it = cache_.find(user_id);
        return (it != cache_.end()) ? it->second : "Unknown";
    }

    // 【写操作】：独占写锁，阻塞所有读和写
    void updateStatus(int user_id, const std::string& status) {
        std::unique_lock<std::shared_mutex> lock(rw_mtx_);
        cache_[user_id] = status;
    }
};

```

## 2. 极致性能方案：COW (Copy-On-Write，写时复制)

利用 `std::atomic` 配合 `std::shared_ptr` 实现**读操作完全无锁**，写操作时深拷贝一份新数据再原子替换。

```cpp
#include <iostream>
#include <memory>
#include <atomic>
#include <string>
#include <unordered_map>
#include <mutex>

class ConfigManager {
private:
    using ConfigMap = std::unordered_map<std::string, std::string>;
    
    // 指向只读配置对象的原子指针
    std::atomic<std::shared_ptr<const ConfigMap>> config_ptr_;
    std::mutex write_mtx_; // 保证同一时间只有一个写操作

public:
    ConfigManager() {
        // 初始化空配置
        config_ptr_.store(std::make_shared<const ConfigMap>());
    }

    // 【读操作】：完全无锁，性能达到极限！
    std::string get(const std::string& key) const {
        // 原子获取当前配置副本的引用（仅引用计数+1，零数据拷贝）
        auto current_config = config_ptr_.load(); 
        auto it = current_config->find(key);
        return (it != current_config->end()) ? it->second : "";
    }

    // 【写操作】：深拷贝新数据，原子替换指针
    void set(const std::string& key, const std::string& value) {
        std::lock_guard<std::mutex> lock(write_mtx_);
        
        // 1. 获取旧数据并拷贝一份全新的数据表 (Copy)
        auto old_config = config_ptr_.load();
        auto new_config = std::make_shared<ConfigMap>(*old_config);

        // 2. 在新数据表上修改
        (*new_config)[key] = value;

        // 3. 原子更新指针 (Swap)，后续新的读线程立刻看到新配置
        config_ptr_.store(new_config);
    }
};

```

## 3. 双缓冲区切换 (Double Buffering)

维护两个固定 Buffer，读线程只读当前激活（Active）的 Buffer；写线程在后台（Shadow）Buffer 修改完后瞬间原子切换索引。

```cpp
#include <iostream>
#include <atomic>
#include <vector>
#include <mutex>

class DoubleBufferRoutingTable {
private:
    using RouteTable = std::vector<std::string>;
    
    RouteTable buffers_[2];         // 两个固定的缓冲区
    std::atomic<int> active_idx_{0}; // 当前激活的 Buffer 索引 (0 或 1)
    std::mutex write_mtx_;           // 保护写操作的互斥锁

public:
    // 【读操作】：完全无锁，直接读取 Active Buffer
    RouteTable getRoutes() const {
        int idx = active_idx_.load(std::memory_order_acquire);
        return buffers_[idx]; 
    }

    // 【写操作】：在后台 Buffer 修改，一步原子切换
    void updateRoutes(const RouteTable& new_routes) {
        std::lock_guard<std::mutex> lock(write_mtx_);

        // 1. 计算后台 (Shadow) Buffer 的索引
        int inactive_idx = 1 - active_idx_.load(std::memory_order_relaxed);

        // 2. 在后台 Buffer 上做修改
        buffers_[inactive_idx] = new_routes;

        // 3. 一步完成切换！
        active_idx_.store(inactive_idx, std::memory_order_release);
    }
};

```

## 4. 语言级优化支持：Go 语言 `sync.Map`

Go 官方标准库内置的 `sync.Map` 专门针对“**读多写少，且 Key 变更少**”的场景做过了极致优化（内部维持了一个只读的 `read` map 和一个需要加锁的 `dirty` map）。

```go
package main

import (
	"fmt"
	"sync"
)

type SafeCache struct {
	m sync.Map
}

// 【读操作】：几乎全无锁（直接命中内部 read map）
func (c *SafeCache) Get(key string) (string, bool) {
	val, ok := c.m.Load(key)
	if !ok {
		return "", false
	}
	return val.(string), true
}

// 【写操作】：直接 Store
func (c *SafeCache) Set(key, value string) {
	c.m.Store(key, value)
}

func main() {
	var cache SafeCache
	cache.Set("server_status", "ONLINE")

	if val, ok := cache.Get("server_status"); ok {
		fmt.Println("Status:", val)
	}
}

```

### 代码总结小卡片：

* **想要代码最简单，通用场景：** 选 `1. 读写锁 (std::shared_mutex)`
* **数据量较小，要求极致读取吞吐：** 选 `2. COW` 或 `3. 双缓冲区`
* **Go 语言开箱即用：** 直接选 `4. sync.Map`
