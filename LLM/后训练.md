# Foundation Model Post-Training (SFT, RLHF, DPO & Reasoning) Complete Interview Guide & Solutions

---

## Role & Technical Scope Overview
A **Post-Training / Alignment Engineer** transforms raw pre-trained base foundation models into instruction-following, aligned, safe, and reasoning-capable AI systems (e.g., ChatGPT, Claude, LLaMA-Instruct, DeepSeek-R1, OpenAI o1).

The core technical pillars evaluated in Post-Training interviews include:
1. **Supervised Fine-Tuning (SFT) & Instruction Tuning**: Data curation/synthesis, loss masking, packing without padding, catastrophic forgetting, and Parameter-Efficient Fine-Tuning (PEFT / LoRA / QLoRA / DoRA).
2. **Reward Modeling (RM)**: Bradley-Terry preference modeling, pairwise ranking loss, margin loss, reward hacking (Goodhart’s Law), and length/verbosity bias mitigation.
3. **Reinforcement Learning from Human/AI Feedback (RLHF / PPO)**: 4-model architecture (Actor, Critic, Ref, Reward), Generalized Advantage Estimation (GAE), KL-penalty mechanics, and PPO training stability.
4. **Direct Preference Optimization (DPO) & Direct Alignment**: Mathematical derivation of DPO from the optimal RLHF policy, implicit rewards, and modern variants (IPO, KTO, SimPO, ORPO).
5. **Reasoning Models, RL with Verifiable Rewards (RLVR) & GRPO**: DeepSeek-R1 / Group Relative Policy Optimization (GRPO), Process vs. Outcome Reward Models (PRM vs. ORM), Chain-of-Thought (CoT) emergence, and Test-Time Compute.
6. **Distributed Post-Training Systems**: Colocated vs. disaggregated actor-learner frameworks (Ray + vLLM + Megatron/FSDP), iterative online DPO pipelines, and inference-training co-scheduling.

# Part 1: Supervised Fine-Tuning (SFT) & Parameter-Efficient Fine-Tuning (LoRA)

---

### Question 1: SFT Loss Formulation, Masking & Sequence Packing
> **What is the standard loss function for Supervised Fine-Tuning (SFT)? Why is prompt token loss masked out? How does sequence packing (Sample Packing) with FlashAttention eliminate padding token waste?**

#### Solution:

```
Unmasked vs. Masked SFT Loss:
Prompt Tokens (X):       [ "User:", "What", "is", "2+2?", "\n" ]  ===> Loss = 0 (MASKED / Ignored)
Completion Tokens (Y):   [ "Assistant:", "4", "<EOS>" ]          ===> Loss = CrossEntropy (Active)
```

#### 1. SFT Loss Formulation with Prompt Masking
Given an input prompt sequence $X = (x_1, x_2, \dots, x_n)$ and target completion $Y = (y_1, y_2, \dots, y_m)$:
* **Autoregressive Language Modeling Loss**:
  $$\mathcal{L}_{\text{SFT}}(\theta) = -\sum_{t=1}^m \log P_\theta(y_t \mid x_1, \dots, x_n, y_1, \dots, y_{t-1})$$
* **Why Mask Prompt Tokens ($X$)?**
  * The model must learn **conditional response generation** ($P(Y \mid X)$), not memorize the distribution of prompts ($P(X)$).
  * Calculating loss on prompt tokens penalizes the model for phrasing differences in human queries, causing gradient interference and degrading conversational flexibility. In PyTorch, prompt token target labels are set to `-100` (`CrossEntropyLoss(ignore_index=-100)`).

#### 2. Sequence Packing (Sample Packing) without Cross-Contamination
* **Padding Waste**: In traditional batching, short dialogues are padded with `<PAD>` tokens to the maximum sequence length (e.g., 4096 tokens). Often **$>50\%$ of compute is wasted on pad tokens**.
* **Packing Mechanism**: Multiple independent conversations are concatenated into a single contiguous 4096-token sequence:
  $$\text{Packed Buffer} = [ \text{Seq}_1, \text{Seq}_2, \text{Seq}_3, \dots ]$$
* **Preventing Cross-Sequence Attention Leakage**:
  * Using **FlashAttention VarLen** (Variable Length API with cumulative sequence lengths `cu_seqlens = [0, 512, 1800, 4096]`), attention heads are restricted strictly within individual sequence boundaries without passing information across sequences.

### Question 2: LoRA, QLoRA, and DoRA Mathematical Mechanics
> **Derive the mathematical formula for LoRA (Low-Rank Adaptation). How does QLoRA achieve 4-bit fine-tuning without precision loss? What is DoRA (Weight-Decomposed LoRA)?**

#### Solution:

```
LoRA Forward Pass:
Input X ---> [ Frozen Pretrained Base Weight W_0 (d x k) ] ---------> ( + ) ---> Output h
        |                                                              ^
        +---> [ Down-Projection A (d x r) ] ---> [ Up-Projection B (r x k) ] * (alpha / r)
              (Initialized: N(0, sigma^2))      (Initialized: Strictly 0)
```

#### 1. LoRA Formulation & Initialization
For a pre-trained linear weight matrix $W_0 \in \mathbb{R}^{d \times k}$, LoRA decomposes the weight update $\Delta W$ into low-rank matrices $B \in \mathbb{R}^{d \times r}$ and $A \in \mathbb{R}^{r \times k}$ (where rank $r \ll \min(d, k)$):

$$h = W_0 x + \Delta W x = W_0 x + \frac{\alpha}{r} (B \cdot A) x$$

* **Scaling Factor $\frac{\alpha}{r}$**: $\alpha$ is a constant hyperparameter. When varying rank $r$, $\frac{\alpha}{r}$ stabilizes the learning rate dynamics.
* **Initialization Trick**:
  * Matrix $A$ is initialized with random Gaussian noise $\mathcal{N}(0, \sigma^2)$.
  * Matrix $B$ is initialized **strictly to $0$**.
  * At step 0: $\Delta W = B \cdot A = 0$, ensuring the model starts exactly from the pre-trained base model state without perturbation.

#### 2. QLoRA (Quantized Low-Rank Adaptation)
* **NF4 (NormalFloat 4)**: An information-theoretically optimal quantile quantization data type for normally distributed neural network weights.
* **Double Quantization (DQ)**: Quantizes the quantization scale factors themselves (saving an additional 0.37 bits per parameter).
* **Paged Optimizers**: Employs CUDA Unified Memory to automatically page optimizer states to CPU RAM during activation spikes, preventing GPU OOM.
* *Result*: Fine-tunes a 70B parameter model on a single 48GB GPU (e.g., A6000).

#### 3. DoRA (Weight-Decomposed Low-Rank Adaptation)
* Decomposes weight matrix into **Magnitude** ($m \in \mathbb{R}^{1 \times k}$) and **Direction** ($V \in \mathbb{R}^{d \times k}$):
  $$W = m \frac{V}{\|V\|_c} = m \frac{W_0 + B A}{\|W_0 + B A\|_c}$$
* Decoupling directional updates from magnitude scaling mirrors the gradient dynamics of full fine-tuning, closing the remaining accuracy gap between LoRA and full SFT.

# Part 2: Reward Modeling (RM) & Human Preference

---

### Question 3: Bradley-Terry Preference Modeling & Reward Loss Formulation
> **Derive the Bradley-Terry preference loss used in Reward Model training. What is Margin Loss? How do you prevent reward hacking and verbosity bias?**

#### Solution:

#### 1. Bradley-Terry Preference Model
Human preference between winning response $y_w$ and losing response $y_l$ given prompt $x$ is modeled as:

$$P(y_w \succ y_l \mid x) = \sigma(r_\psi(x, y_w) - r_\psi(x, y_l)) = \frac{1}{1 + e^{-(r_\psi(x, y_w) - r_\psi(x, y_l))}}$$

Where $r_\psi(x, y)$ is a scalar reward score predicted by the reward model (typically a pre-trained LLM where the unembedding head is replaced by a linear projection $\mathbb{R}^d \rightarrow \mathbb{R}$).

#### 2. Pairwise Binary Cross-Entropy Loss
Given a dataset of pairwise comparisons $\mathcal{D} = \{(x, y_w, y_l)\}$:

$$\mathcal{L}_{\text{RM}}(\psi) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma\left( r_\psi(x, y_w) - r_\psi(x, y_l) - M(x, y_w, y_l) \right) \right]$$

* **Margin $M(x, y_w, y_l)$**: An optional margin offset proportional to the human annotator confidence or preference strength gap (e.g., $M = 0.5$ if $y_w$ is significantly better, $M = 0.1$ if slightly better).

#### 3. Mitigating Reward Hacking (Goodhart’s Law) & Verbosity Bias
* **Reward Hacking**: The policy exploits quirks in the reward model (e.g., generating endless polite filler text, repetitive bullet points, or hallucinating authoritative citations).
* **Verbosity Bias Mitigation**:
  1. **Length-Normalized Loss**: Penalize reward if length delta does not correlate with quality.
  2. **Length-Balanced Pair Synthesis**: Include synthetic pairs where the shorter response is high quality and the longer response is repetitive/verbose.
  3. **Ensemble of Reward Models**: Train $K$ independent reward models with different seeds/architectures; use the conservative lower bound (e.g., $\min_k r_k(x, y)$ or $\mu - \lambda \sigma$) as the training signal.

# Part 3: Reinforcement Learning from Human Feedback (RLHF / PPO)

---

### Question 4: PPO 4-Model Architecture & Generalized Advantage Estimation (GAE)
> **Explain the 4-model architecture in PPO RLHF (Actor, Critic, Reference, Reward). What role does GAE play in balancing bias and variance?**

#### Solution:

```
                                      [ Prompt x ]
                                           |
                 +-------------------------+-------------------------+
                 |                                                   |
                 v                                                   v
        +------------------+                               +------------------+
        |   Actor Model    |                               | Reference Model  |
        |  \pi_\theta(y|x) |                               | \pi_{ref}(y|x)   |
        +------------------+                               +------------------+
                 | (Rollout y)                                       | (Logprob ref)
                 +-------------------------+-------------------------+
                                           |
                                           v
                             +---------------------------+
                             |   KL-Divergence Penalty   |
                             |  R = r(x,y) - \beta * KL  |
                             +---------------------------+
                                           ^
                                           |
                                 +-------------------+
                                 |   Reward Model    |
                                 |     r_\psi(x,y)   |
                                 +-------------------+
                                           | Total Reward R_t
                                           v
                             +---------------------------+
                             |       Critic Model        |
                             |      V_\phi(s_t)          |
                             +---------------------------+
                                           |
                                           v
                             [ GAE Advantage Estimation \hat{A}_t ]
                                           |
                                           v
                             [ PPO Policy Gradient Update ]
```

#### 1. The 4 Distinct Models in PPO
1. **Actor Policy $\pi_\theta$ (Active/Trained)**: Generates response tokens $y \sim \pi_\theta(\cdot \mid x)$. Receives policy gradient updates.
2. **Critic / Value Model $V_\phi$ (Active/Trained)**: Predicts expected cumulative reward from state $s_t$: $V_\phi(s_t) \approx \mathbb{E}[R_t]$.
3. **Reference Model $\pi_{\text{ref}}$ (Frozen Base SFT Model)**: Computes reference log-probabilities $\pi_{\text{ref}}(y_t \mid s_t)$ to enforce a KL penalty, preventing the actor from collapsing or drifting away from natural language.
4. **Reward Model $r_\psi$ (Frozen)**: Evaluates the final completed sequence $(x, y)$ and provides the scalar objective reward $r(x, y)$.

#### 2. Generalized Advantage Estimation (GAE)
* **Per-Token Combined Reward**:
  $$R_t = \begin{cases} -\beta \left( \log \pi_\theta(y_t \mid s_t) - \log \pi_{\text{ref}}(y_t \mid s_t) \right) & \text{if } t < T \\ r_\psi(x, y) - \beta \left( \log \pi_\theta(y_T \mid s_T) - \log \pi_{\text{ref}}(y_T \mid s_T) \right) & \text{if } t = T \end{cases}$$
* **Temporal Difference (TD) Error**:
  $$\delta_t = R_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t)$$
* **GAE Advantage $\hat{A}_t$ Formula**:
  $$\hat{A}_t^{\text{GAE}(\gamma, \lambda)} = \sum_{l=0}^{T - t - 1} (\gamma \lambda)^l \delta_{t+l}$$
  * $\lambda = 0$: $\hat{A}_t = \delta_t$ (TD(0): Lowest variance, higher bias).
  * $\lambda = 1$: Monte Carlo return (Zero bias, highest variance).
  * *Standard Tuning*: $\gamma = 1.0, \lambda = 0.95$.

### Question 5: PPO Clipped Surrogate Objective & Training Stability
> **Write the PPO-Clip loss equation. Why is the probability ratio $r_t(\theta)$ clipped? What engineering tricks ensure PPO training stability?**

#### Solution:

#### 1. PPO-Clip Objective Function
$$\mathcal{L}_{\text{PPO}}(\theta) = -\hat{\mathbb{E}}_t \left[ \min\left( r_t(\theta) \hat{A}_t, \; \text{clip}(r_t(\theta), 1 - \epsilon, 1 + \epsilon) \hat{A}_t \right) \right]$$

Where the importance sampling probability ratio is:
$$r_t(\theta) = \frac{\pi_\theta(y_t \mid s_t)}{\pi_{\theta_{\text{old}}}(y_t \mid s_t)} = \exp\left( \log \pi_\theta(y_t \mid s_t) - \log \pi_{\theta_{\text{old}}}(y_t \mid s_t) \right)$$

#### 2. Why Clipping is Crucial
* If an action yields a huge positive advantage ($\hat{A}_t > 0$), a naive policy gradient would make an unbounded update to maximize $r_t(\theta)$, destroying the model's language fluency in a single gradient step.
* The $\text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)$ operator bounds the gradient step whenever $r_t(\theta) > 1 + \epsilon$ (for positive advantage) or $r_t(\theta) < 1 - \epsilon$ (for negative advantage), ensuring small, safe trust-region updates (typically $\epsilon = 0.2$).

#### 3. Practical PPO Stability Engineering Tricks
1. **Advantage Normalization**: Normalize $\hat{A}_t$ across the mini-batch: $\hat{A}_t \leftarrow \frac{\hat{A}_t - \mu_A}{\sigma_A + \epsilon}$.
2. **Value Function Clipping**: Clip the critic update similarly: $V_{\text{clipped}} = V_{\text{old}} + \text{clip}(V_\phi - V_{\text{old}}, -\epsilon_v, \epsilon_v)$.
3. **Reward Scaling / Whitening**: Normalize raw scalar rewards from the reward model to have standard deviation $\approx 1.0$.

# Part 4: Direct Preference Optimization (DPO) & Direct Alignment

---

### Question 6: Mathematical Derivation of DPO (Direct Preference Optimization)
> **Derive the Direct Preference Optimization (DPO) objective from the constrained RLHF objective. How does DPO eliminate the need for an explicit Reward Model and Critic network?**

#### Solution:

#### 1. The Constrained RLHF Objective
The classic RLHF objective maximizes expected reward subject to a KL-divergence constraint:

$$\max_{\pi} \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi} [r(x, y)] - \beta \mathbb{D}_{\text{KL}}(\pi(y \mid x) \parallel \pi_{\text{ref}}(y \mid x))$$

Expanding the expectation and KL term:
$$= \max_{\pi} \sum_y \pi(y \mid x) r(x, y) - \beta \sum_y \pi(y \mid x) \log \frac{\pi(y \mid x)}{\pi_{\text{ref}}(y \mid x)}$$
$$= \max_{\pi} \sum_y \pi(y \mid x) \left[ \frac{r(x, y)}{\beta} - \log \frac{\pi(y \mid x)}{\pi_{\text{ref}}(y \mid x)} \right]$$

#### 2. Closed-Form Optimal Policy Solution
Using Gibbs distribution / calculus of variations, the optimal policy $\pi^*$ has the closed form:

$$\pi^*(y \mid x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y \mid x) \exp\left( \frac{r(x, y)}{\beta} \right)$$

Where $Z(x) = \sum_y \pi_{\text{ref}}(y \mid x) \exp\left( \frac{r(x, y)}{\beta} \right)$ is the partition function.

#### 3. Reparameterizing Reward $r(x, y)$ in Terms of Policy $\pi^*$
Taking the logarithm on both sides:
$$\log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} = \frac{r(x, y)}{\beta} - \log Z(x)$$
$$\mathbf{r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)}$$

#### 4. Substituting Implicit Reward into Bradley-Terry Preference Loss
Recall the Bradley-Terry preference loss:
$$\mathcal{L}_{\text{RM}} = -\mathbb{E}_{(x, y_w, y_l)} \left[ \log \sigma(r(x, y_w) - r(x, y_l)) \right]$$

Substitute our reparameterized reward equation into the difference $r(x, y_w) - r(x, y_l)$:
$$r(x, y_w) - r(x, y_l) = \left( \beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} + \beta \log Z(x) \right) - \left( \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)} + \beta \log Z(x) \right)$$

Notice that the intractable partition function **$\beta \log Z(x)$ cancels out perfectly!**

$$\mathbf{\mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E}_{(x, y_w, y_l)} \left[ \log \sigma\left( \beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)} \right) \right]}$$

* *Why DPO is Transformative*: Allows optimizing the policy directly on preference data with standard supervised cross-entropy-style training, completely eliminating the Reward Model, Critic network, and unstable online RL rollouts!

### Question 7: DPO Variants & Comparison (IPO, KTO, SimPO, ORPO)
> **Compare DPO against modern variants: IPO, KTO, SimPO, and ORPO. What are the key limitations of standard DPO (e.g., reference model overhead, length bias)?**

#### Solution:

| Algorithm | Reference Model Required? | Pairwise Data Required? | Loss Formulation / Core Mechanism | Key Advantage |
| :--- | :--- | :--- | :--- | :--- |
| **DPO** | **Yes** ($\pi_{\text{ref}}$) | **Yes** $(x, y_w, y_l)$ | $-\log \sigma\left( \beta \Delta \log \frac{\pi}{\pi_{\text{ref}}} \right)$ | Stable baseline; direct RLHF equivalence. |
| **IPO (Identity PO)**| **Yes** ($\pi_{\text{ref}}$) | **Yes** $(x, y_w, y_l)$ | $\left( \beta \Delta \log \frac{\pi}{\pi_{\text{ref}}} - \frac{1}{2\beta} \right)^2$ (MSE on logits) | Prevents DPO from overfitting and collapsing log-likelihood on $y_w$. |
| **KTO** | **Yes** ($\pi_{\text{ref}}$) | **No** (Unpaired: $(x, y, \text{is\_good})$) | Maximizes Prospect Theory utility per sample. | Works on unpaired real-world data (thumbs up/down). |
| **SimPO** | **No** (Zero Ref Model) | **Yes** $(x, y_w, y_l)$ | $-\log \sigma\left( \frac{\beta}{|y_w|} \log \pi(y_w) - \frac{\beta}{|y_l|} \log \pi(y_l) - \gamma \right)$ | **Length-normalized & reference-free**. Saves 50% GPU VRAM. |
| **ORPO** | **No** (Zero Ref Model) | **Yes** $(x, y_w, y_l)$ | $\mathcal{L}_{\text{SFT}} + \lambda \mathcal{L}_{\text{OddsRatio}}$ | Combines SFT and Alignment into a **single unified training step**. |

# Part 5: Reasoning Models, RLVR & DeepSeek-R1 / GRPO

### Question 8: Group Relative Policy Optimization (GRPO / DeepSeekMath & R1)
> **How does GRPO (Group Relative Policy Optimization) work? How does it eliminate the Critic model ($V_\phi$) from PPO, and why is this critical for scaling reasoning models?**

#### Solution:

```
PPO Architecture:
[ Actor (100% VRAM) ] + [ Reference (100% VRAM) ] + [ Reward (100% VRAM) ] + [ Critic (100% VRAM) ] ===> 4 Full Models in Memory!

GRPO Architecture (DeepSeek-R1):
[ Actor Model \pi_\theta ] ===> Samples G completions for Prompt q: { o_1, o_2, ..., o_G }
                                    |
                                    v
[ Rule-Based Verifier / Reward ] ==> Scores: { r_1, r_2, ..., r_G }
                                    |
                                    v
[ Group Normalization ] ==========> Advantage: A_i = (r_i - mean(r)) / std(r)  (NO CRITIC MODEL NEEDED!)
```

#### 1. The Critic Bottleneck in Long-CoT Reasoning
* In large reasoning models (e.g., 70B–671B parameters) generating long Chains-of-Thought ($8\text{k}-32\text{k}$ tokens):
  * The Critic model must be of comparable parameter size to the Actor to accurately predict value estimates.
  * Maintaining Actor + Critic + Ref + Reward simultaneously causes massive GPU memory exhaustion and communication overhead.

#### 2. GRPO Mathematical Formulation
For each input prompt $q$, GRPO samples a **group of $G$ outputs** $\{o_1, o_2, \dots, o_G\}$ from the old policy $\pi_{\theta_{\text{old}}}$.
1. **Group Relative Advantage Calculation**:
   $$\hat{A}_i = \frac{r_i - \text{mean}(\{r_1, \dots, r_G\})}{\text{std}(\{r_1, \dots, r_G\})}$$
2. **GRPO Objective Function**:
   $$\mathcal{L}_{\text{GRPO}}(\theta) = -\frac{1}{G} \sum_{i=1}^G \left[ \min\left( \frac{\pi_\theta(o_i \mid q)}{\pi_{\theta_{\text{old}}}(o_i \mid q)} \hat{A}_i, \; \text{clip}\left(\frac{\pi_\theta(o_i \mid q)}{\pi_{\theta_{\text{old}}}(o_i \mid q)}, 1-\epsilon, 1+\epsilon\right) \hat{A}_i \right) - \beta \mathbb{D}_{\text{KL}}(\pi_\theta \parallel \pi_{\text{ref}}) \right]$$
* **Why GRPO is Revolutionary for Reasoning**:
  * Completely **removes the Critic model ($V_\phi$)**, freeing up $>50\%$ GPU memory and compute.
  * Normalizing across multiple candidate completions naturally rewards solutions that discovered the correct answer when peers failed.

### Question 9: Reinforcement Learning with Verifiable Rewards (RLVR) & Emergent CoT
> **What is RLVR (Reinforcement Learning with Verifiable Rewards)? How do rule-based verifiers in Math and Coding elicit emergent reasoning (Chain-of-Thought, self-correction, backtracking) without human labels?**

#### Solution:

#### 1. Verifiable vs. Subjective Rewards
* **Subjective Tasks (Chat, Creative Writing)**: Require fuzzy, noisy neural Reward Models prone to reward hacking.
* **Verifiable Tasks (Mathematics, Competitive Programming, Formal Logic)**:
  * Ground truth is strictly deterministic.
  * **Rule-Based Verifiers**:
    * Math: Regex output extraction matched against ground truth ($\text{Boxed Answer} == \text{Target}$).
    * Code: Python sandbox execution passing unit test suites (e.g., LeetCode/HumanEval test cases).
    * Reward is binary: $r \in \{0, 1\}$ (or partial credit for passing $k/N$ unit tests). Zero reward hacking possible!

#### 2. How RLVR Sparks "Aha! Moments" (Emergent Reasoning)
```
Reinforcement Learning Exploration Loop:
Step 1: Policy generates CoT: "Let me calculate 15 * 14. 15 * 10 = 150. 15 * 4 = 50. Total = 200." -> Wrong (r = 0)
Step 2: Policy explores alternative paths in group G.
Step 3: Policy generates: "Wait, let me double check. 15 * 4 is 60, not 50! So 150 + 60 = 210." -> Correct (r = 1)
Step 4: Gradient update heavily reinforces the self-reflection and backtracking behavior!
```

* Under pure RL exploration with binary outcome verification:
  * The model autonomously learns to allocate **more test-time compute tokens** (longer CoT reasoning chains).
  * Self-correction, verification, backtracking ("Wait, let me re-evaluate...", "Let me check for edge cases"), and structured step-by-step proofs emerge naturally without explicit step-by-step human demonstrations.

### Question 10: Process Reward Models (PRM) vs. Outcome Reward Models (ORM)
> **What is the difference between an Outcome Reward Model (ORM) and a Process Reward Model (PRM / "Let's Verify Step by Step")? How does PRM power Monte Carlo Tree Search (MCTS) and Best-of-N at test time?**

#### Solution:

```
Outcome Reward Model (ORM):
Step 1 ---> Step 2 (Error made here!) ---> Step 3 ---> Step 4 ---> Final Answer: Wrong ===> Score = 0 (No feedback on where error occurred!)

Process Reward Model (PRM):
Step 1 (Score: 0.98) ---> Step 2 (Score: 0.12 - ERROR DETECTED!) ---> Step 3 (Score: 0.05) ===> Pinpoints exact failure point!
```

#### 1. ORM vs. PRM
* **ORM (Outcome Reward Model)**: Takes the full solution sequence and outputs a single scalar score $r(x, y)$ reflecting the final answer correctness.
  * *Limitation*: Suffers from credit assignment ambiguity (cannot tell which intermediate reasoning step was flawed).
* **PRM (Process Reward Model)**: Assigns a step-level correctness score $r(x, y_1, \dots, y_t)$ to every individual reasoning step.
  * *Advantage*: Immediately penalizes faulty intermediate derivations even if the final guess accidentally matches.

#### 2. Test-Time Compute Search with PRMs
1. **Best-of-N Sampling**: Sample $N$ independent solutions; select the solution with the highest cumulative step-level PRM score:
   $$\text{Score}(Y) = \prod_{t=1}^K \text{PRM}(\text{step}_t)$$
2. **Tree-Search (MCTS / Beam Search over Reasoning Steps)**:
   * Expand reasoning tree step-by-step.
   * At each step, prune low-scoring branches based on PRM evaluations and expand only the most promising intermediate paths.

### Question 11: Distributed RLHF System Architecture (Ray + vLLM + Megatron/FSDP)
> **How do modern RLHF/PPO training systems (e.g., OpenRLHF, verl, DeepSpeed-Chat) orchestrate rollouts and training across distributed GPU clusters? How do they avoid GPU idle bubbles between generation and gradient updates?**

#### Solution:

```
Colocated Ray + vLLM Distributed Post-Training Architecture:

[ Worker GPU 0 - 7 (Actor / Learner Nodes) ]
  |
  +--- Phase 1: High-Throughput Rollout Generation
  |    - vLLM Engine handles KV cache & Continuous Batching.
  |    - Generates G completions per prompt in parallel.
  |
  +--- Phase 2: In-Memory Weight & Activation Handoff
  |    - Zero-copy tensor pointer swap directly in VRAM.
  |
  +--- Phase 3: Distributed Training / Gradient Step
       - Megatron-LM / PyTorch FSDP computes forward/backward pass.
       - Updates Actor parameters and syncs new weights to vLLM engine.
```

#### 1. The Hybrid Workload Challenge in RLHF
* **Generation Phase (Rollout)**: Memory-bandwidth bound autoregressive token generation. Requires continuous batching, PagedAttention, and fast inference kernels (vLLM / TensorRT-LLM).
* **Training Phase (Learner)**: Compute-bound distributed backward passes (FSDP / Megatron TP+PP).
* **Historical Bottleneck**: Storing separate GPU clusters for inference and training resulted in massive network transfer bottlenecks and $50\%$ idle GPU time.

#### 2. Modern Colocated Architecture (verl / OpenRLHF)
* **Colocation on Same GPUs**: The Actor inference engine (vLLM) and training framework (FSDP/Megatron) reside on the **exact same physical GPUs**.
* **Dynamic Memory & Execution Handoff**:
  1. **Rollout**: vLLM takes control of GPU memory, allocates PagedAttention KV caches, and streams completions at maximum generation throughput.
  2. **Memory Release**: vLLM frees its KV cache memory pool.
  3. **Backward Step**: FSDP allocates activation memory, computes gradients, updates weights via Adam optimizer.
  4. **In-Place Weight Sync**: The updated weights in PyTorch are synced directly to vLLM's memory pointers with **zero inter-node network transfer**.

## Final Quick Reference Sheet for Post-Training Interviews
* **SFT Loss Masking**: Always mask prompt tokens (`ignore_index=-100`) to condition strictly on $P(Y \mid X)$.
