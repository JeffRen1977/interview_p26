**3A** = **AE (Auto Exposure)** + **AWB (Auto White Balance)** + **AF (Auto Focus)**。  
Senior Staff 不只背公式，还要讲清：

1. **Stats 从哪来 → 算法怎么决策 → 参数写回 Sensor/ISP 哪一层**  
2. **预览实时 3A** 与 **拍照计算摄影（多帧 HDR/夜景）** 如何分工  
3. **高通 Spectra/CamX** 与 **Google Pixel 成像栈** 的架构差异与可借鉴点  

---

## 0. 一句话总览

```text
Sensor 出 Bayer
   → ISP 前端算 Stats（亮度/颜色/对焦统计）
   → 3A 算法（闭环控制）
   → 下一帧：改 Exposure/Gain（Sensor）+ 改 ISP gain/CCM（管道）+ 驱动马达（VCM）
   → 同时 ISP 全链路把 Bayer 做成可显示的 YUV
```

**闭环本质：** 3A 是带延迟的反馈控制系统（通常控制的是 **N+1 / N+2 帧**，不是当前已曝光完的帧）。

## 1. ISP Pipeline：每一级在干什么？

下面按「经典手机 ISP + 高通 Spectra 映射」说明。真实 SoC 模块名会变，但 **信息流顺序与物理约束** 高度稳定。

### 1.1 端到端流水线

```text
[Sensor Bayer RAW]
    │
    ▼
 Black Level / Pedestal 去掉 ───────── 去掉传感器暗电平，避免抬黑/压黑
    │
    ▼
 LSC (Lens Shading Correction) ────── 补偿镜头中心亮四周暗、色斑
    │
    ▼
 Bad Pixel Correction ─────────────── 修坏点，避免 demosaic 放大成彩斑
    │
    ▼
 Bayer NR / Bilateral（可选）──────── 在马赛克域去噪，保留边缘
    │
    ├────────────────────────────────► Stats Engine（给 3A）
    │                                   BG / BHIST / BF / RS ...
    ▼
 AWB Gains（R/B digital gain）─────── 按估计光源校正白平衡
    │
    ▼
 Demosaic ─────────────────────────── Bayer → 全分辨率 RGB
    │
    ▼
 CCM / Color Correction ───────────── 传感器原色 → 目标色空间（sRGB/P3）
    │
    ▼
 Gamma / Tone Mapping ─────────────── 12/10bit 线性 → 显示非线性；HDR 压到 8/10bit
    │
    ▼
 YUV 转换 + Chroma NR / Sharpen ───── 观感：噪声、清晰度、伪轮廓
    │
    ▼
 Crop / Scale / Rotation / EIS ────── 输出多路：Preview / Video / Still / Analysis
    │
    ▼
[NV12 / P010 / UBWC YUV / JPEG / HEIF]
```

### 1.2 各阶段目的（面试可逐条背）

| 阶段 | 目的 | 不做会怎样 | Staff 追问点 |
| --- | --- | --- | --- |
| **BLC (Black Level)** | 减去暗电流/偏置 | 阴影发灰或发黑、AWB/AE 基准错 | 不同 gain/温度下 black level 是否动态？ |
| **LSC** | 校正光学 vignetting 与色阴影 | 四角暗、四角色偏 | Table 与变焦/光圈（若可变）如何切换？ |
| **BPC** | 识别并替换坏点 | 亮点/黑点，demosaic 后彩点 | 动态坏点 vs OTP 静态表 |
| **Bayer NR** | 马赛克域降噪 | 低光 demosaic 拉链/彩噪更重 | 与 YUV NR、多帧 NR 如何分工？ |
| **Stats** | 为 3A 提供压缩统计 | 3A 只能瞎猜或读全图（太慢） | 网格大小、ROI、人脸权重 |
| **AWB gains** | 乘 R/B（有时 G）使灰看起来灰 | 整图偏黄/偏蓝 | 与 CCM 的职责边界 |
| **Demosaic** | 恢复每像素 RGB | 无法做正常彩色图 | 拉链、假色、AI demosaic |
| **CCM** | 色矩阵匹配色彩科学 | 饱和度/色相不对 | 多光源 CCM 插值 |
| **Gamma / Tone** | 动态范围适配显示 | 灰雾或死黑死白 | Global vs local tone；与 HDR10 关系 |
| **YUV NR / LT M / Sharpen** | 观感打磨 | 脏、糊、或过锐光晕 | 皮肤/天空分区处理 |
| **Scaler / EIS** | 多分辨率与防抖 | 预览与录像 FOV 不一致 | EIS 裁切对 AE ROI 的影响 |

### 1.3 高通 Spectra 硬件怎么拆？

口语映射（便于和面试官对齐术语）：

| 模块 | 典型职责 |
| --- | --- |
| **IFE (Image Front End)** | 收 CSID 的 Bayer；做前端校正、**出 Stats**、下采样/裁切、写 RAW/IDEAL RAW、部分预览路径 |
| **BPS (Bayer Processing)** | 更重的 Bayer 域处理（视世代），常服务静物/多帧路径 |
| **IPE (Image Processing Engine)** | RGB/YUV 域：色调、NR、锐化、多路 scaler 输出 |
| **CDM** | 把 per-frame 寄存器包推到硬件，减 CPU MMIO |
| **Stats / 3A** | 多在 **CPU / Hexagon** 跑算法，读 IFE stats，写回 Sensor（CCI）与 ISP 参数 |

**Staff 金句：**  
IFE 偏「实时前端 + 统计」；IPE 偏「画质与多输出」；3A 是「用统计闭环控制下一帧」的软件状态机。

## 2. 3A 通用原理（与厂商无关）

### 2.1 AE — Auto Exposure

**目标：** 把场景亮度控制到目标（通常不是单纯“中灰 18%”，而是带人脸/高光保护/闪烁抑制的 metering）。

**执行器（actuators）：**

1. **Sensor exposure time**（行数 / 微秒）— 见 [sensor.md](./sensor.md)  
2. **Analog gain / Digital gain**  
3. 有时还有 **ISP digital gain**、光圈（少数机型）、ND  

详细逐步计算见下方 **§2.4 AE 计算详解**。

### 2.2 AWB — Auto White Balance

**目标：** 估计场景照明的色温/色度，使中性色接近中性。

**执行器：**

- **R/B channel gains**（Bayer 或 RGB 域）  
- **CCM 选择/插值**（不同色温矩阵）  

详细逐步计算见下方 **§2.5 AWB 计算详解**。

### 2.3 AF — Auto Focus

**目标：** 最大化感兴趣区域锐度 / 对准目标深度。

**执行器：** VCM / 闭环马达位置（DAC code）。

**传感方式：**

| 类型 | 原理 | 优劣 |
| --- | --- | --- |
| **CDAF** | 搜焦最大化对比度 | 准但慢，来回拉风箱 |
| **PDAF** | 左右瞳相位差估离焦方向与量 | 快；需标定，弱光/低对比易漂 |
| **Dual Pixel** | 全像素相位差 | 大面积 PDAF，Pixel 常用 |
| **Laser / ToF** | 主动测距 | 暗光近距快；远距/强光受限 |
| **Hybrid** | PDAF 粗到位 + CDAF 精修 | 手机主流 |

**状态机：** `INACTIVE / PASSIVE_SCAN / ACTIVE_SCAN / FOCUSED_LOCKED / NOT_FOCUSED_LOCKED…`（Android AF state）。

## 2.4 AE 计算详解（Senior Staff 手撕级）

### A. 光电基础：亮度与曝光的线性关系

在 RAW 线性域（减去 black level 之后），同一场景近似满足：

$$
L \propto E \times t \times g_{\mathrm{analog}} \times g_{\mathrm{digital}}
$$

其中：

- \(E\)：场景照度（物体反射进镜头的光）  
- \(t\)：曝光时间（秒）  
- \(g_{\mathrm{analog}}, g_{\mathrm{digital}}\)：模拟/数字增益（倍数，不是 dB）  

定义 **Exposure Value 乘积（常见工程名叫 sensitivity product / exp-gain product）**：

$$
P = t \times g_{\mathrm{analog}} \times g_{\mathrm{digital}}
$$

则测到的图像亮度（stats）近似：

$$
Y_{\mathrm{meas}} \approx k \cdot E \cdot P
$$

AE 的任务：调 \(P\)，使 \(Y_{\mathrm{meas}}\) 接近目标 \(Y_{\mathrm{target}}\)。

### B. 从 Stats 得到 \(Y_{\mathrm{meas}}\)（测光）

ISP 通常给 **分块 Bayer/YUV 均值**（如 BG stats）或 **直方图（BHIST）**。

**1) 网格加权测光（最常用）**

把画面划成 \(M \times N\) 块，每块均值 \(Y_{ij}\)（可由 \(0.3R+0.6G+0.1B\) 或直接用 G）：

$$
Y_{\mathrm{meas}} = \frac{\sum_{ij} w_{ij}\, Y_{ij}}{\sum_{ij} w_{ij}}
$$

权重 \(w_{ij}\) 来自：

| 模式 | 权重怎么设 |
| --- | --- |
| Center-weighted | 中心高、四周低 |
| Spot | 仅中心一小块为 1 |
| Face AE | 人脸框内块权重 ≫ 背景 |
| Highlight priority | 对过亮块降权或单独惩罚 |

**2) 直方图测光（防过曝）**

看亮度直方图累积：

- 若超过阈值 \(T_{\mathrm{hi}}\) 的像素比例 \(> r_{\mathrm{clip}}\) → 判定过曝，需要 **减小 \(P\)**  
- 暗部占比过高 → 可增大 \(P\)，但常让位于高光保护  

**工程混合：**  
`Ymeas = mix(网格加权Y, 直方图约束后的Y)`，高光超标时强制压曝光。

### C. 计算下一帧的曝光乘积 \(P_{\mathrm{next}}\)

最简比例控制（面试先写这个）：

$$
P_{\mathrm{next}} = P_{\mathrm{cur}} \times \frac{Y_{\mathrm{target}}}{Y_{\mathrm{meas}} + \varepsilon}
$$

- \(Y_{\mathrm{target}}\)：目标亮度（tuning 表，可随 lux/人脸/EV compensation 变）  
- EV 补偿：App 设 EV = +1 通常意味着目标按 **2×** 变亮（每档 EV ≈ \(2^{\mathrm{EV}}\)）  

$$
Y_{\mathrm{target}}' = Y_{\mathrm{target}} \times 2^{\mathrm{EV}}
$$

**带限幅的收敛（更像真机）：**

```text
ratio = Y_target / Y_meas
ratio = clamp(ratio, 1/max_step, max_step)   # 例如每帧最多 ±20%~40%，防抽动
P_next = clamp(P_cur * ratio, P_min, P_max)
```

也可用 **PID**：误差 \(e = \log Y_{\mathrm{target}} - \log Y_{\mathrm{meas}}\)（在 log 曝光域更稳）。

### D. 把 \(P\) 拆成 \((t, g_a, g_d)\)——Exposure Table

约束：

1. \(t \in [t_{\min}, t_{\max}]\)，且 \(t\) 不能超过当前帧长（与 VTS/fps 绑定）  
2. Anti-banding：\(t\) 尽量落在 \(1/100, 1/120, 1/50, \ldots\) 附近（50/60Hz 灯光）  
3. 优先：先加满合理 \(t\) → 再 \(g_a\) → 最后 \(g_d\)（噪声最差）  

**拆解伪代码：**

```text
# 输入: P_next
# 输出: exposure_time, again, dgain

t = P_next / (again_min * dgain_min)
t = min(t, t_max_for_fps)
t = snap_to_antibanding(t)          # 对齐到 1/100 或 1/120 网格

remain = P_next / t
again = clamp(remain, again_min, again_max)
remain = remain / again
dgain = clamp(remain, 1.0, dgain_max)

# 若仍不够亮: 降低 fps → 增大 t_max（拉长 VTS），或接受目标欠曝
```

**曝光时间 ↔ 行数（写 Sensor 寄存器）：**

$$
t = N_{\mathrm{lines}} \times \frac{\mathrm{HTS}}{f_{\mathrm{pixclk}}}
\quad\Rightarrow\quad
N_{\mathrm{lines}} = \mathrm{round}\left(t \times \frac{f_{\mathrm{pixclk}}}{\mathrm{HTS}}\right)
$$

且 \(N_{\mathrm{lines}} \le \mathrm{VTS}\)；不够则 **增大 VTS（降帧率）**。详见 [sensor.md](./sensor.md)。

**Gain 倍数 ↔ Gain Code：**  
Sensor 厂商表，例如近似 \( \mathrm{code} \approx \mathrm{gain} \times 128 \)（仅示例，以 spec 为准）。Android 上报的 `SENSOR_SENSITIVITY`（ISO）与 again/dgain 的映射也要在 HAL 里维护。

### E. Lux Index / BV（高通 tuning 常用 trigger）

许多栈会先估一个场景亮度索引（名字各异：lux index、BV、brightness value）：

$$
\mathrm{LuxIndex} \propto -\log(P) + \log(Y_{\mathrm{meas}}) + C
$$

直觉：同样 \(Y\)，若用了更大的 \(P\)，说明场景更暗 → lux index 更高（暗）。  
Tuning 用 lux index 去查：目标 Y、最大曝光、NR 强度、AE 收敛速度等。

### F. 人脸 AE 的具体改法

```text
Y_face = weighted_mean(stats inside face boxes)
Y_bg   = weighted_mean(stats outside)
Y_meas = α * Y_face + (1-α) * Y_bg     # α 随人脸面积/置信度变，如 0.6~0.85

# 逆光：人脸暗、背景亮
if Y_bg >> Y_face and highlight_not_blown:
    raise Y_target_for_face or increase α
elif highlight_blown:
    protect highlights first (reduce P), rely on later tone/HDR
```

### G. Pixel / HDR+ 向的 AE 计算差异（概念）

单帧 AE：解 \(P\) 使 \(Y_{\mathrm{meas}} \approx Y_{\mathrm{target}}\)。  

HDR+ 类：

1. 估场景动态范围（直方图两端）  
2. 选 **短曝** \(P_{\mathrm{short}}\) 保护高光（甚至 \(Y\) 故意偏暗）  
3. 连拍 \(N\) 帧，融合后等效抬暗部  
4. Night Sight：总积分 \(T_{\mathrm{total}} = \sum t_i\)，但单帧 \(t_i\) 受运动模糊约束  

面试公式不必展开融合，但要能说：**优化目标从“单帧 Y”变成“融合后的动态范围与噪声”。**

### H. AE 手算小例子（白板）

当前：\(t=10\mathrm{ms}\)，again=2，dgain=1 → \(P=0.02\)  
测得 \(Y=40\)，目标 \(Y=80\)（8bit 域示意）  

$$
P_{\mathrm{next}} = 0.02 \times \frac{80}{40} = 0.04
$$

若 \(t_{\max}=20\mathrm{ms}\)（50fps 限制更短；此处假设 30fps 可到 ~33ms）：  
可取 \(t=20\mathrm{ms}\)，again=2，dgain=1 → \(P=0.04\)。  
若 \(t\) 已到顶，则 again → 4。

## 2.5 AWB 计算详解（Senior Staff 手撕级）

### A. 问题定义

理想中性物体在某光源下的 RAW 响应为 \((R,G,B)\)。AWB 求增益，使校正后：

$$
R' = g_R R,\quad G' = g_G G,\quad B' = g_B B
$$

满足 \(R' \approx G' \approx B'\)（或落在目标白点）。通常固定 \(g_G=1\)，只调 \(g_R,g_B\)：

$$
g_R = \frac{G}{R},\quad g_B = \frac{G}{B}
\quad\text{（对“白点”样本）}
$$

全图没有完美白点时，用统计估计等价白点 \((R_w,G_w,B_w)\)，再：

$$
g_R = \frac{G_w}{R_w},\quad g_B = \frac{G_w}{B_w}
$$

### B. Stats 预处理

对每个网格块（或像素子集）：

1. 减 black level，坏点剔除  
2. 丢掉过暗/过饱和块（噪声大或 clip，不可信）  
3. 得到块均值 \((R_{ij}, G_{ij}, B_{ij})\)  
4. 转到色度坐标，例如：

$$
r = \frac{R}{R+G+B},\quad b = \frac{B}{R+G+B}
$$

或：

$$
\frac{R}{G},\ \frac{B}{G}
$$

### C. 经典算法 1：Gray World

假设场景 RGB 平均为灰：

$$
\bar{R}=\mathrm{mean}(R),\ 
\bar{G}=\mathrm{mean}(G),\ 
\bar{B}=\mathrm{mean}(B)
$$

$$
g_R = \frac{\bar{G}}{\bar{R}},\quad g_B = \frac{\bar{G}}{\bar{B}},\quad g_G = 1
$$

**失败场景：** 大面积单色（红墙、草地足球场）→ 平均不是灰 → 严重偏色。

### D. 经典算法 2：White Patch / Max-RGB

假设最亮像素接近光源色：

$$
R_{\max}=\max R,\ 
G_{\max}=\max G,\ 
B_{\max}=\max B
$$

$$
g_R = \frac{G_{\max}}{R_{\max}},\quad g_B = \frac{G_{\max}}{B_{\max}}
$$

**失败场景：** 高光镜面反射、裁切、有色最亮物体。

### E. 经典算法 3：Gamut / 相关色温约束（手机常用骨架）

1. 在 \((R/G,\ B/G)\) 平面收集可信块  
2. 与 **预标定的光源轨迹**（Planckian locus 附近的色温曲线）比对  
3. 估计 CCT（相关色温，单位 K）与距离 locus 的 tint  
4. 用 CCT 查表或插值得到 \((g_R,g_B)\) 与 CCM  

示意：

```text
points = {(R/G, B/G) for valid blocks}
cct, tint = project_to_planckian_locus(points)   # 或加权投票
(gR, gB) = lookup_awb_gain(cct, tint)
CCM      = interp_ccm(cct)                       # 例如 2850K~6500K 多组矩阵
```

**CCM 与 AWB gains 分工：**

- Gains：对角、快速、粗平衡  
- CCM：\(3\times 3\)，校正通道串扰与色域，随 CCT 切换  

校正顺序常见为：

```text
RAW → LSC → * AWB gains → demosaic → * CCM → ...
```

（具体前后以 ISP 管线为准，面试说清“增益在 Bayer、矩阵在 RGB”即可。）

### F. 置信度与时域平滑（真机必备）

```text
# 每帧原始估计
gR_raw, gB_raw, confidence = estimate_awb(stats)

# 低置信（大单色、极暗、高饱和）→ 少更新或沿用历史
alpha = confidence * alpha_max          # 例如 0.05~0.3
gR = (1-alpha)*gR_prev + alpha*gR_raw
gB = (1-alpha)*gB_prev + alpha*gB_raw
```

高 ISO 时 stats 噪声大 → 强制更小 `alpha`，否则预览会“呼吸式”偏色。

### G. 人脸 / 肤色约束（连结 Pixel Real Tone 思路）

```text
if face_detected:
    # 肤色在 (R/G, B/G) 上有先验带状区域（按 CCT 变化）
    # 不要把深肤色当“不够白”而狂加 gR/gB 把人拉成灰白
    awb_bias = skin_preserving_bias(face_chroma, cct)
    gR, gB = apply_bias(gR, gB, awb_bias)
```

**Staff 表述：** 目标不是数学上最灰，而是 **偏好一致的、符合人种肤色科学的观感白平衡**。

### H. ML-AWB（Pixel 与新旗舰路径）

输入：分块色度直方图 / 缩略图特征  
输出：CCT 或直接 \((g_R,g_B)\) + confidence  

部署要点（高通面试也爱问）：

- 跑在 DSP/NPU，分辨率远低于全图  
- 超时则回退经典 AWB  
- 输出必须平滑，禁止每帧跳变  

### I. AWB 手算小例子（Gray World）

某灰卡区域均值：\(R=100,\ G=200,\ B=150\)（已减黑电平）

$$
g_R = 200/100 = 2.0,\quad g_B = 200/150 \approx 1.33,\quad g_G=1
$$

校正后：\(R'=200,\ G'=200,\ B'=200\) → 中性灰。

若全图是大面积绿草把 \(\bar{G}\) 抬得很高，Gray World 会错误地压绿、抬红蓝 → 草地发灰、皮肤发品，这就是要用 **locus 约束 / ML / 人脸先验** 的原因。

### J. 和 AE 的耦合

| 耦合点 | 处理 |
| --- | --- |
| 曝光变化导致 clip | 过曝块不进 AWB 统计 |
| 高 again 噪声 | 提高平滑、提高有效块阈值 |
| LSC 不准 | 四角色偏，AWB 被边角污染 → 用中心权重或先 LSC |
| 多摄切换 | 两路 gains/CCM 做映射，避免跳变 |

## 2.6 AE / AWB 计算流程串起来（一张图）

```text
Frame N 曝光完成
    │
    ├─ Image → ISP preview
    └─ Stats
         │
         ├─ AE:
         │     Ymeas(weighted) → ratio → P_next
         │     → split (t, again, dgain) → antibanding → Sensor CCI
         │
         └─ AWB:
               valid blocks → estimate white (GW / locus / ML)
               → (gR,gB) + CCT → smooth → ISP gains + CCM
    │
    ▼
Frame N+1 / N+2 使用新参数曝光与处理
```

**记住：** 你算的是 **未来帧**；评估收敛要看延迟后的 \(Y_{\mathrm{meas}}\) 是否进目标窗（如 ±5%）。

## 3. Qualcomm 方案：CamX + Spectra 上的 3A

### 3.1 控制闭环（高通语境）

```text
IFE 硬件
  ├─ 图像 →（可选）IPE → Preview YUV
  └─ Stats packets ──► CamX Stats / 3A Node (CPU or DSP)
                            │
                            ├─ AE  → Exposure + Gain ──CCI──► Sensor
                            ├─ AWB → Gains + CCM ───────────► IFE/IPE 寄存器
                            └─ AF  → Lens position ─────────► Actuator driver
                            │
                            ▼
                     打包进下一帧 Config Packet（CDM）
```

要点：

- **Stats 与图像同行**：同一帧曝光条件下统计，决策通常作用于后续帧（pipeline delay）。  
- **Chromatix / Tuning**：大量查表与触发器（trigger：lux index、gain、CCT、face…）控制 3A 与 ISP 分支。  
- **Per-frame control**：预览每帧可更新；拍照可能锁 3A 或走独立 bracketing 序列。  

### 3.2 高通 Stats 常见类型（面试够用）

| Stats | 主要服务 |
| --- | --- |
| **BG / AWB stats** | 分块 R/G/B 均值 → AWB、部分 AE |
| **BHIST** | 亮度/通道直方图 → AE、高光判定 |
| **BF / AF stats** | 对焦滤波能量 → CDAF/PDAF 辅助 |
| **RS / row sum 等** | 闪烁检测、卷帘曝光辅助 |
| **Face ROI** | 来自 FD 算法，写入 metering 权重 |

### 3.3 AE on Qualcomm（实务）

落地时就是 §2.4 的闭环，挂在 CamX Stats Node 上：

1. 读 BG/BHIST → \(Y_{\mathrm{meas}}\) / lux index  
2. 查 Chromatix 得 \(Y_{\mathrm{target}}\)、最大 \(t\)、收敛速度  
3. \(P_{\mathrm{next}} = P_{\mathrm{cur}} \times Y_{\mathrm{target}} / Y_{\mathrm{meas}}\)，再拆 `(t, again, dgain)`  
4. Anti-banding；必要时改 VTS  
5. 经 CCI 写入 Sensor；不足部分用 ISP dg  

**Staff 题：暗光预览为何变糊？**  
AE 拉长曝光 → 运动模糊；或拉高 gain → 噪点让 AF stats 变差。应用策略可能是：降 fps 换曝光、开多帧 NR、或限制最长曝光。

### 3.4 AWB on Qualcomm

落地时就是 §2.5：

1. BG stats 网格 → 滤可信块  
2. 经典 / ML 估 CCT 与 \((g_R,g_B)\)  
3. 按 CCT 插值 CCM  
4. 时域平滑后写入 IFE/IPE；高 gain 降置信度  

### 3.5 AF on Qualcomm

1. PDAF 像素/相位数据（sensor embedded 或 ISP 解析）→ 置信度 + defocus  
2. 置信度高：直接跳马达；低：CDAF fine search  
3. CAF：场景变化检测触发 rescan  
4. 多摄：副摄 AF 与主摄深度/映射协同（SAT）  

### 3.6 与 Android HAL3 的接缝

- App 设 `CONTROL_AE_MODE` / `AWB_MODE` / `AF_TRIGGER`  
- HAL 上报 `SENSOR_EXPOSURE_TIME`、`SENSOR_SENSITIVITY`、`COLOR_CORRECTION_GAINS`、`LENS_FOCUS_DISTANCE`、`CONTROL_*_STATE`  
- **Partial Result** 可先把 AF/AE state 送上 Framework（见 [android_framework.md](./android_framework.md)）  

**Vendor Tag：** 夜景帧数、AE bracket list、锁 3A for ZSL 等，多走 QTI/OEM tag。

## 4. Google Pixel 方案：计算摄影驱动的 3A 哲学

> Pixel 不是“不用 3A”，而是 **实时 3A 保证预览可用**，**静物画质大量交给多帧+ML 后处理**。面试对比时强调 **系统分工**，不要贬低任一边。

### 4.1 架构差异（和高通手机 OEM 典型栈比）

| 维度 | Qualcomm 路线（多数 OEM） | Google Pixel 路线 |
| --- | --- | --- |
| **核心卖点载体** | Spectra ISP + CamX + Tuning（Chromatix）可复制到多家 OEM | 软硬一体：定制 Sensor/ISP 路径 + **GCam 算法栈** |
| **预览** | 强依赖 ISP 实时管线 + 3A | 同样需要实时 3A/ISP，但产品默认更敢用短曝光+后期 |
| **静物** | MFNR/MFHDR/AI-NR 节点挂在 Chi Graph | **HDR+ / Super Res Zoom / Night Sight** 等为产品主路径 |
| **测光** | 经典分块 + 人脸；调参极重 | 面向 **burst 合成** 的曝光策略（常更偏短曝叠帧） |
| **AWB** | 统计+触发器表；近年也上 ML | 长期推 **学习型 AWB**、与人像/肤色科学（Real Tone）强绑定 |
| **AF** | PDAF hybrid 为主 | Dual Pixel PDAF 体系成熟；算法与计算摄影联动（运动、人像） |
| **交付形态** | 芯片厂商提供可 tuning 的参考栈 | 垂直整合，算法与热点机型强绑定 |

### 4.2 Pixel / HDR+ 思路下的 AE

经典 ISP AE：让 **单帧** 曝光“好看”。  

HDR+ 类 AE：

- 选择 **故意偏短** 或 bracket 的曝光，使高光少过曝  
- 连拍多帧对齐融合，抬暗部、压噪声  
- Night Sight：更长总积分时间，但拆成多帧以控制模糊与热噪  

**Staff 表述：**  
Pixel 把“正确曝光”部分定义成 **融合后的结果正确**，而不是每一帧都中灰。因此预览 AE 与连拍 AE 策略可以分离（preview 要跟手，still 要动态范围）。

### 4.3 Pixel 思路下的 AWB

- 不只 Gray World：用场景理解 / ML 估计光照  
- **人脸与肤色**：避免统一“拍白”造成深肤色失真（Real Tone 产品叙事）  
- 与多帧合成：各帧白平衡一致性，避免融合彩迹  

### 4.4 Pixel 思路下的 AF

- Dual Pixel 提供稠密相位数据 → 快速、区域灵活  
- 与人像/运动：追踪 ROI，连拍期间焦平面策略  
- 计算摄影仍依赖 **光学对准**：再强的软件也不能凭空恢复完全失焦的高频（但可做一定 deblur）  

### 4.5 对高通 AE 岗位的启发（面试加分）

在高通侧做 Senior Staff，被问 “Pixel 为什么夜景更好看？” 建议答：

1. **曝光策略服务多帧**，不是单帧 ISP tone 硬拉  
2. **对齐 + fusion + 心理工学调色** 投入远大于单帧 gamma  
3. **端到端垂直优化**（sensor 噪声模型、ISP 线性域、算法一体）  
4. 高通栈可追赶的工程点：Chi 上 MFHDR/MFNR 质量、3A 与多帧调度、人脸 AWB、运动场景的 exposure time 上限策略

## 5. 预览 3A vs 拍照 / 视频：调度关系

```text
Preview path (实时，≤33ms 级预算)
  IFE → Stats → 3A → 更新下一帧
  IFE/IPE → YUV → Display

Still path (可长到百毫秒~数秒)
  锁焦/锁或重算曝光序列 → 多帧 RAW/YUV → 融合 → JPEG/HEIF

Video path
  3A 更强调稳定（少抽动）；EIS 与 AE 曝光上限博弈
```

**冲突例：**

- 夜景连拍要长总曝光，预览仍要 30fps → **两套 exposure policy**  
- 录像防抖要裁切，AE ROI 必须跟 EIS 窗口走  
- 逻辑多摄切换要 **3A warm-up**，否则闪一下（见 [android_framework.md](./android_framework.md) §5）

## 6. 调参 / Tuning 心智模型（Senior Staff）

无论 Chromatix 还是 Pixel 内部工具，逻辑类似：

1. **Trigger**：lux、gain、CCT、face ratio、HDR ratio…  
2. **Region**：不同 trigger 区间用不同表（AE target、AWB bias、NR strength…）  
3. **Transition**：插值，避免跳变  
4. **约束**：热、带宽、fps、法律闪烁、肤色  

**排障顺序建议：**

```text
先问：是真的场景光照问题，还是 stats/ROI 错了，还是执行器没写进 Sensor？
  → 查 metadata：exposure/gain/ccm/awb gains/af 状态
  → 查 stats dump / AE 收敛曲线
  → 查 CCI 是否在 VBlank 更新成功（sensor.md）
  → 最后才改“观感向”IPE 参数
```

## 8. 高频 Q&A

**Q: AE 和 Gamma 谁负责“变亮”？**  
A: AE 改光子与增益（信噪比物理层）；Gamma/tone 改编码曲线（显示层）。暗光只靠 tone 拉亮 = 放大噪声。

**Q: 下一帧曝光怎么由当前亮度算出来？**  
A: \(P_{\mathrm{next}} = P_{\mathrm{cur}} \times Y_{\mathrm{target}} / Y_{\mathrm{meas}}\)，再按 antibanding 与 again 优先策略拆成 `(t, again, dgain)`，最后换成行数写 Sensor。见 §2.4。

**Q: AWB 的 \(g_R,g_B\) 怎么来？**  
A: 估白点 \((R_w,G_w,B_w)\) 后 \(g_R=G_w/R_w,\ g_B=G_w/B_w\)。白点可用 Gray World、White Patch、Planckian locus 投影或 ML。见 §2.5。

**Q: AWB gain 和 CCM 区别？**  
A: Gains 近似对角缩放通道；CCM 是 3×3，处理色耦合与色域。粗平衡用 gains，精细色彩科学用 CCM。

**Q: 为什么 3A 总是“慢一帧”？**  
A: 统计来自已曝光帧；Sensor 曝光参数对后续帧生效；再加 ISP/CPU 流水线深度。

**Q: PDAF 准为什么还要 CDAF？**  
A: 相位标定误差、低纹理、串扰、微对焦需求；CDAF 做 fine tune。

**Q: Qualcomm vs Pixel，面试怎么表态？**  
A: 高通强在可复制的硬件 ISP + 可 tuning 的完整栈与带宽性能；Pixel 强在计算摄影产品化与垂直整合。Senior Staff 要能把 Pixel 的多帧/ML 测光思想 **落到 CamX 节点与 3A 策略**，而不是只会复述产品功能。
