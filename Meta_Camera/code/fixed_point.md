# 定点数学与无 FPU 运算

你的清单里「fast integer square root / fixed-point」只在表格里出现过一次。它值得一道独立的题：3A 跑在没有硬件浮点的 DSP / M 核上，gamma 用截断而不是圆整会在暗部**肉眼可见地断层**。

实现与自测：[`fixed_point.cpp`](./fixed_point.cpp)

```bash
c++ -std=c++17 -Wall -Wextra -O2 fixed_point.cpp -o fixed_point && ./fixed_point
```

---

## 1. Q 格式

Qm.n 表示 n 位小数：`value = raw / 2^n`。Q16.16 存在 `int32_t` 里，范围 $[-32768, 32768)$，分辨率 $1/65536$。

**乘法必须先加宽**：

```c
int64_t p = (int64_t)a * b;        // 2n 位小数
return (p + (1 << (Q-1))) >> Q;    // 圆整回 n 位
```

写成 `(a * b) >> 16` 在 `int32_t` 里，**只要有一个操作数超过 1.0 就溢出**——这是这题的头号 bug。测试里用 $200 \times 150 = 30000$ 专门打这个点。

**圆整要对称**：正数加半、负数减半。只写 `+half` 的话负数被拉向 $-\infty$，长链运算会累积单向偏置。

## 2. 整数开方（精确 floor）

逐位二进制法：无除法、无浮点，32 位输入 16 次迭代。

```c
root <<= 1;  rem = (rem << 2) | (n >> 30);  n <<= 2;
if (rem > root) { rem -= root | 1; root |= 2; }
```

验收条件写成不变式，比对拍浮点可靠：

$$
r^2 \le n < (r+1)^2
$$

`.cpp` 里对 $[0, 10^5)$ 穷举 + `0xFFFFFFFF` 边界都验了。

**Q16.16 的 sqrt 要先左移 16 位再开方**，而 `raw << 16` 需要 64 位——用 `uint32_t` 做会静默截断所有大于 1.0 的值。这是本题第二个考点。

## 3. 牛顿法求倒数

除法器慢或者没有时：$x_{k+1} = x_k(2 - d\,x_k)$，二次收敛。先把 $d$ 归一化到 $[0.5, 1)$，用 $48/17 - (32/17)d$ 起步，4 次迭代到 Q16.16 精度，最后把归一化的移位补回去。

## 4. 相机里的两个实际落点

**Gamma 用 LUT，不要每像素 `pow()`。** 256 项一次建好。`+0.5` 圆整不能省——截断相当于全局丢半个 LSB，暗部曲线最陡的地方直接断层。

验收：gamma = 1.0 必须是**恒等映射**。这个测试专抓「除以 256 而不是 255」的经典 off-by-one。

**数字增益 + 黑电平**（每像素都要做的那步）：

```c
v = src - black;  if (v < 0) v = 0;          // 低于黑电平要 clip，不能回绕
out = (v * gain_q8_8 + 128) >> 8;            // +128 圆整
if (out > white) out = white;                 // clamp 到白电平
```

`v` 必须是有符号中间量。用 `uint16_t` 直接减会回绕成 65000，暗场变成一片雪花——真机上出现过的 bug。

## 5. 追问清单

- **为什么不用 float？** Cortex-M0/M4 无 FPU（或只有单精度）、DSP 上 float 吞吐低、定点结果**逐位可复现**（IQ 回归测试需要 bit-exact）。
- **精度怎么选？** 增益 Q8.8 够（1/256 步进）；CCM 系数要 Q2.14（范围小但要精度）；坐标/畸变要 Q16.16。说得出「按动态范围和精度需求分别选 Q」就够了。
- **饱和运算：** ARM 有 `SSAT/USAT` 和 `QADD` 单指令饱和；C 里要手写 clamp。
- **除法：** 很多 MCU 没有硬件除法器。定点里尽量把除法换成「乘倒数 + 移位」，倒数在配置时算一次。
