# IR LED 光斑检测与亚像素质心

**清单上原本没有，但 Meta controller tracking 就是干这个的。** Quest 手柄的 IR LED 星座、眼动的普尔钦斑、结构光的点阵，全都是同一个 pipeline：**阈值 → 连通域 → 亚像素质心**。

实现与自测：[`blob_centroid.cpp`](./blob_centroid.cpp)

```bash
c++ -std=c++17 -Wall -Wextra -O2 blob_centroid.cpp -o blob_centroid && ./blob_centroid
```

---

## 1. 连通域标记（CCL）两种写法

| 写法 | 复杂度 | 什么时候说这个 |
|------|--------|----------------|
| BFS/DFS 泛洪 | O(N) | 好写，但要随机访问整幅图 + 一个队列 |
| **两遍 + 并查集** | O(N·α) | 只看**上一行**，可以跑在 2 行 line buffer 上——嵌入式真实做法 |

BFS 用**显式队列不要递归**：一个全白的 VGA 图会递归 30 万层直接爆栈。

两遍法的核心是「因果邻居」——只查 W / NW / N / NE 四个已经标过的位置，取最小标签，其余用 `union` 记等价。**U 字形**是必测用例：两条竖臂先拿到不同标签，底部连上时必须合并。一遍法在这里必错。

并查集用 **path halving + 小根优先**：

```c
while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }
parent[max(a,b)] = min(a,b);
```

**4 连通 vs 8 连通** 要主动问。只在角上相接的两点，8 连通是一个 blob，4 连通是两个。IR 光斑一般用 8 连通。

## 2. 亚像素质心：按强度加权

二值质心只能给到整像素，tracking 精度不够。用**强度减去阈值**做权重：

$$
c_x = \frac{\sum_i (I_i - T + 1)\, x_i}{\sum_i (I_i - T + 1)}
$$

减 `T` 是关键——不减的话每个像素都带一个基座（pedestal），质心被拉向 ROI 几何中心，亮度分布越偏移误差越大。`.cpp` 里的测试构造了一个真值 $x = 4.30$ 的高斯光斑，验证加权质心误差 < 0.1 px 且明显优于 bbox 中心。

好的实现能到 **0.05–0.1 px**，这直接决定手柄的角度分辨率。

## 3. 过滤与排序

```
area < min_area  ->  热噪点 / 坏点，扔
area > max_area  ->  过曝晕开、太阳、环境 IR 泛光，扔
```

输出必须**按亮度排序**（或任何确定性顺序）。tracker 做星座匹配时不能容忍「同一帧两次跑出来顺序不同」。

## 4. 追问清单

- **饱和怎么办：** LED 打到 255 时质心失真（顶部被削平）。做法是控制曝光让峰值落在 200 左右，或者只用未饱和的边缘像素拟合高斯。
- **为什么用全局阈值：** 因为主动 IR 照明 + 短曝光 + 窄带滤光片下背景几乎全黑。环境光强时要换**局部/自适应阈值**（积分图算局部均值，见 [`integral_image.md`](./integral_image.md)）。
- **怎么和 tracker 接：** blob 只给 2D 观测；星座的 ID 关联靠 LED **时序调制**（每颗 LED 按不同 pattern 闪）+ 上一帧 pose 的重投影预测。
- **性能：** VGA@90fps 全图 CCL 在 DSP 上都紧张。真机上用**上一帧 ROI 预测**，只在小窗口里跑，全图搜索只在丢失时做。
- **和 `number_of_islands` 的关系：** 同一道题。面试官问岛屿数量时，你可以顺势说「这就是我们做 LED 检测的第一步，实际还要出质心」——立刻把 LeetCode 变成领域对话。
