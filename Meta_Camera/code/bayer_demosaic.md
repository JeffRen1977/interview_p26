# Bayer Bilinear Demosaic

Camera 岗的“本命题”。难点不是插值公式，是**判断当前像素是什么颜色**，以及**边界怎么处理才不破坏 CFA 相位**。

实现与自测：[`bayer_demosaic.cpp`](./bayer_demosaic.cpp)

```bash
c++ -std=c++17 -Wall -Wextra -O2 bayer_demosaic.cpp -o bayer_demosaic && ./bayer_demosaic
```

---

## 1. CFA 相位

四种排布用**左上 2×2** 命名：

```
 RGGB      GRBG      GBRG      BGGR
 R G       G R       G B       B G
 G B       B G       R G       G R
```

查表比一堆 `if` 干净，也不会写错：

```c
q = ((r & 1) << 1) | (c & 1);         // 0=TL 1=TR 2=BL 3=BR
color = tbl[pattern][q];              // 0=R 1=G 2=B
```

Bayer 中 **G 占一半**（棋盘格），R 和 B 各占四分之一——这就是为什么 G 通道的插值质量决定整幅图的锐度。

## 2. 双线性规则

| 当前像素 | R | G | B |
|----------|---|---|---|
| **R 位** | 自身 | 上下左右 4 邻域平均 | 4 个对角平均 |
| **B 位** | 4 个对角平均 | 上下左右 4 邻域平均 | 自身 |
| **G 位** | 同行或同列的 2 个邻域平均 | 自身 | 另一个轴的 2 个平均 |

G 位最容易写错：R 在**水平轴还是垂直轴**取决于这一行是 R 行还是 B 行。代码里用 `cfa_color(pattern, r, c-1)` 直接问左邻居的颜色，比推导 `(r&1)`/`(c&1)` 组合安全。

## 3. 边界必须“反射 2”，不是反射 1

这是这题真正的坑。普通图像处理 clamp 或反射 1 格都行；Bayer 不行——**镜像必须保持奇偶性**，否则边界像素拿到的是错误颜色的邻居，整圈边框会偏色。

```c
if (v < 0)   return -v;             // -1 -> 1,  -2 -> 2   奇偶不变
if (v >= n)  return 2*n - 2 - v;    //  n -> n-2
```

**验收测试：** 构造一张 R 全等于 100、G 全等于 200、B 全等于 300 的平场，demosaic 之后**每个像素**（含四条边和四个角）都必须精确等于 (100, 200, 300)。边界策略错了这个测试立刻挂。`.cpp` 里对四种 pattern 都跑了这个测试。

## 4. 追问

- **伪彩 / 拉链（zipper）：** 双线性在高频边缘会出彩色摩尔纹。改进方向是**边缘自适应**：先用梯度判断插值方向（水平 vs 垂直），再沿低梯度方向插值（Hamilton-Adams / VNG / Malvar）。说得出名字和思路即可，不用手写。
- **为什么先 BLC/LSC 再 demosaic：** 黑电平和暗角是 per-CFA-channel 的增益，必须在 RAW 域做完，否则插值会把误差混进三个通道。
- **2×2 binning（`.cpp` 里有）：** 一个 CFA quad 出一个 RGB 像素，半分辨率、零伪彩、四分之一算力。tracking 路径和缩略图路径就是这么做的。
- **位深：** 用 `uint16_t` 承载 10/12-bit RAW；`(a+b+1)/2` 和 `(a+b+c+d+2)/4` 的 `+1 / +2` 是圆整，别丢。
