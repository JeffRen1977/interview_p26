# 积分图（SAT）与 O(1) Box Filter

[`box_filter.md`](./box_filter.md) 的自然追问：「现在把 15×15 的模糊做到每像素 225 次读取以下」。

实现与自测：[`integral_image.cpp`](./integral_image.cpp)

```bash
c++ -std=c++17 -Wall -Wextra -O2 integral_image.cpp -o integral_image && ./integral_image
```

---

## 1. 定义与查询

$$
S(r,c)=\sum_{i<r}\sum_{j<c} I(i,j)
$$

多开一行一列的零边（尺寸 $(H{+}1)\times(W{+}1)$），矩形查询就**不需要任何边界判断**：

$$
\text{sum}(x_0,y_0,x_1,y_1) = S(y_1{+}1,x_1{+}1) - S(y_0,x_1{+}1) - S(y_1{+}1,x_0) + S(y_0,x_0)
$$

四次访存、三次加减、与窗口大小无关。

构建也是 O(N)，一遍带行内累加：

```c
cur[c+1] = prev[c+1] + row_acc;   // row_acc 是本行前缀和
```

## 2. **累加器位宽是这题真正的考点**

8-bit 像素、4096×4096：$255 \times 2^{24} = 2^{32} - 2^{24}$，**刚好卡进 `uint32_t`**。再大一点，或者输入是 10-bit RAW，立刻溢出。

面试时先说这句再写循环：「除非能证明上界，我用 `uint64_t`；这是带宽代价，不是正确性代价。」

补充：SAT 对**浮点**同样危险——大数吃小数，相减后有效位大量丢失。所以 SAT 一般只用整数。

## 3. 边界语义要和参考实现对齐

用 SAT 做 replicate padding 时，不能只 clamp 查询矩形——那样窗口变小了，除数也得跟着变。`.cpp` 里 clamp 矩形**并且**除以 clamp 后的面积（= 「可用像素的平均」），并且提供了同语义的朴素实现做逐像素比对（rad = 1/2/3/7 全部 bit-identical）。

面试时明确说出你选了哪种边界语义，比默默选一种更重要。

## 4. 相机里真正的用途：AE 分区测光

3A 每帧要 N×M 个分区的亮度均值。**一张 SAT 回答全部分区**，而不是每个分区各扫一遍。`.cpp` 里的 `ae_zone_means` 就是这个。

其他用途：
- **自适应阈值**（局部均值），接 [`blob_centroid.md`](./blob_centroid.md)
- **Haar 特征 / 人脸检测**（Viola-Jones 的原始动机）
- 快速 **NCC / SSD 模板匹配** 的分母项
- **方差**需要平方和积分图（第二张 SAT，位宽要求更狠）

## 5. 追问

- **什么时候不值得？** 半径小（3×3、5×5）时**可分离卷积**更快：两趟 1D，缓存友好、不需要额外的宽累加器。SAT 在半径大、或同一帧要查很多不同尺寸窗口时才赢。
- **滑动窗口累加** 是另一条路：水平方向维护一个运行和，每列进一个出一个，O(1)/px 且不需要 SAT 的内存。半径固定时这是最优解。
- **内存代价：** `uint64_t` 的 SAT 是 8 bytes/px，4K 就是 66MB——在眼镜的 DDR 预算里这不是小数目。分块（tiled SAT）可以压下来。
